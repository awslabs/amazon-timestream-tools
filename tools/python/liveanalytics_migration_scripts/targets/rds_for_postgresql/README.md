# PostgreSQL CSV Ingestion Tool

## Overview

This tool provides a high-performance solution for loading CSV files into PostgreSQL databases. It leverages multi-threading and connection pooling to process multiple files in parallel, significantly reducing data loading time.

## Features

- **Multi-threaded Processing**: Load multiple CSV files simultaneously
- **Connection Pooling**: Efficiently manage database connections
- **Automatic Column Detection**: Dynamically extract column names from CSV headers
- **Retry Logic**: Handle transient errors with exponential backoff
- **File Management**: Moves processed files to a designated directory so retrying is resuming but not restarting
- **Comprehensive Logging**: Detailed logs for monitoring and troubleshooting
- **Error Notifications**: Optional SNS notifications for failures
- **Secure Credentials**: Retrieve database passwords from AWS Secrets Manager

## Prerequisites

- Python 3.6+
- Aurora/RDS Postgres Cluster schema, database and table with correct datatypes created.
- AWS credentials configured if using Secrets Manager and Simple Notification Services
- Download CSV files generated by Timestream unload tool

## Usage

```bash
python copy_postgres.py \
  --table TABLE_NAME \
  --database DATABASE_NAME \
  --csv_files_dir "/path/to/csv/files/*.csv" \
  --host DATABASE_HOST \
  --secret_name SECRET_NAME \
  [--schema SCHEMA] \
  [--user USERNAME] \
  [--port PORT] \
  [--parallel_threads THREADS] \
  [--processed_dir PROCESSED_DIR] \
  [--logs_dir LOGS_DIR] \
  [--sns_topic_arn SNS_TOPIC_ARN]
```

## Parameters

### Required Parameters

- `--table`: Target PostgreSQL table name
- `--database`: PostgreSQL database name
- `--csv_files_dir`: Directory or glob pattern for CSV files
- `--host`: Aurora/RDS Postgres cluster writer endpoint
- `--secret_name`: AWS Secrets Manager secret containing database password

### Optional Parameters

- `--schema`: PostgreSQL schema (default: public)
- `--user`: PostgreSQL username (default: postgres)
- `--port`: PostgreSQL port (default: 5432)
- `--parallel_threads`: Number of concurrent threads (default: 10)
- `--processed_dir`: Directory for processed files (default: auto-generated)
- `--logs_dir`: Directory for log files (default: ./postgres-ingestion-logs)
- `--sns_topic_arn`: SNS topic ARN for failure notifications

## How It Works

1. **Initialization**: Parse arguments and set up logging
2. **Authentication**: Retrieve database credentials from AWS Secrets Manager
3. **Connection**: Create a connection pool to PostgreSQL
4. **File Discovery**: Find all CSV files matching the specified pattern
5. **Parallel Processing**: Distribute files across multiple threads
6. **Data Loading**: For each file:
   - Extract column names from the CSV header
   - Build a dynamic COPY command
   - Load data with retry logic for transient errors
   - Move successfully processed files to the processed directory
7. **Notification**: Send SNS notifications for any failures
8. **Completion**: Log summary statistics

## Example

```bash
python copy_postgres.py \
  --table customers \
  --database sales \
  --csv_files_dir "/data/csv_files/*partition*/*.csv" \
  --host database-1.cluster-123456789012.us-east-1.rds.amazonaws.com \
  --secret_name  'arn:aws:secretsmanager:us-east-1:123456789012:secret:rds!cluster-xxxxx-xx-xx-xx-xxxxxxxx-xxxxx' \
  --parallel_threads 20 \
  --sns_topic_arn "arn:aws:sns:us-east-1:123456789012:notifications"
```

## Best Practices

1. **Performance Tuning**: Adjust thread count based on available CPU cores and network bandwidth
2. **Error Handling**: Configure SNS notifications for production environments
3. **File Management**: Provide processed directory in a structured way (e.g., by date, table, or database) to facilitate tracking and troubleshooting
4. **Security**: Store database credentials in AWS Secrets Manager
5. **Monitoring**: Check log files for detailed operation information

## Troubleshooting

- **Connection Issues**: Verify database credentials and network connectivity
- **Permission Errors**: Ensure database user has INSERT privileges
- **CSV Format Problems**: Confirm CSV headers match table column names


## Notes

For production workloads with complex requirements, AWS Database Migration Service (DMS) offers a robust and scalable solution. For scenarios where AWS DMS may not be suitable for your specific requirements, we provide this supplementary Python-based PostgreSQL CSV Ingestion Tool for migrating CSV data from S3 to PostgreSQL.
